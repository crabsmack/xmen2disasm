# Phase 2: static recompilation (definition of done)

Goal: X-Men 2 runs natively on Windows as C generated by
[segagenesisrecomp](https://github.com/mstan/segagenesisrecomp), and it is **provably the
same game**: on the same inputs, work RAM and video memory equal the reference emulator's on
every frame of the TAS and the whole corpus, with no interpreter fallback.

Checked by `uv run tools/phase.py 2` (run from this repo; it writes `docs/progress/P2.md`).
Inputs from phase 1: `build/recomp/` and [RECOMP_HANDOFF.md](../RECOMP_HANDOFF.md).

## Where things live

| What | Where |

## Criteria

| ID | Criterion | Check |
|---|---|---|
| K1 | Game repo set up | `$XMEN2_RECOMP` is a git repo; `origin` is the private `crabsmack/XMen2Recomp`; `.gitmodules` pins the engine fork and this repo; no ROM was ever committed (`git log --all` has no `.bin/.gen/.smd` path); Actions disabled on the engine fork |
| K2 | Reference is comparable | every corpus run's `frames.csv` has `ram_crc32,vram_crc32,cram_crc32,vsram_crc32` (and `z80_crc32`, reported only); `uv run emu/export_input.py <run>` writes the run's full input stream as a runner `.input` script |
| K3 | Generated C is complete | `xmen2check.py gen`: 0 unsupported instructions, 0 validator errors, every function in `build/recomp/functions.csv` generated |
| K4 | Release runner builds | `xmen2check.py build`: Release exe exists, newer than the generated C |
| K5 | Boot matches | first 600 TAS frames: all compared columns equal every frame |
| K6 | Whole TAS matches | TAS, all 57,465 frames: all compared columns equal every frame |
| K7 | No fallback, no stubs | the K6 run reports 0 dispatch misses, 0 interpreter (Tier-3) instructions, 0 stub hits, from the runner's own counters |
| K8 | Whole corpus matches | every run of `emu/corpus.py --list` (TAS, idle, fuzz, scenarios): all compared columns equal every frame |
| K9 | Fast enough | uncapped headless Release run of the TAS ≥ 120 frames/s (2x real time) |
| K10 | User verified | `XMen2Recomp/docs/USER_VERIFIED.md` has `user-verified: YYYY-MM-DD` for a Release build, written only on the user's word after they played it (engine PRINCIPLES #25) |

"Compared columns" = `ram_crc32, vram_crc32, cram_crc32, vsram_crc32`. `z80_crc32` is
printed, not gated: the sound CPU's RAM depends on 68000/Z80 timing finer than a frame, and
audio is verified by the user (K10). Excluding any RAM range or changing frame alignment
(e.g. lag frames) needs the user's approval, recorded here.

## The contract the game repo provides

`tools/phase.py` runs these in `$XMEN2_RECOMP` and does the comparing itself, against this
repo's reference. Implement them honestly: they report what the runner did, never fill gaps.

```
uv run tools/xmen2check.py gen   --json   # {"unsupported": N, "validator_errors": N, "functions": ["0BA4A4", ...]}
uv run tools/xmen2check.py build --json   # {"exe": "...", "config": "Release", "ok": true}
uv run tools/xmen2check.py trace --run NAME --input FILE.input --out DIR [--frames N] [--mode recomp] --json
    # plays FILE.input on the Release runner headless; writes DIR/frames.csv with
    # frame,ram_crc32,vram_crc32,cram_crc32,vsram_crc32,z80_crc32 (same definitions as the
    # reference: CRC-32 over 68000-byte-order memory, sampled after each frame) and prints
    # {"frames": N, "dispatch_misses": N, "interp_instructions": N, "stub_hits": N, "fps": F, "exe": "..."}
```

Later phases extend the same tool (their docs say how): `trace --mode handc|native`,
`--renderer vdp|native --fb` (adds an `fb_crc32` column), `types`, `handc`,
`difftest --all`, `lint [--native]`, `build --native`. Phase 2 only needs `gen`, `build`
and `trace --mode recomp`.

Results are cached per (game repo HEAD, engine HEAD, run) in `build/phase_cache.json`; a
dirty game repo is never cached. `uv run tools/phase.py 2 --fresh` ignores the cache.

   upstream has no workflows today), the private repo, the two submodules. Model the layout
   on the engine's Sonic 1 game repo, but use the engine's

   minimal `puyo/puyo_spec.c` GameSpec. There is no scaffold in the engine. Write

2. **K2** (in this repo): extend `emu/` to record VRAM/CRAM/VSRAM/Z80 CRCs per frame
   (BizHawk memory domains), re-run the corpus (`uv run emu/corpus.py --force`; committed
   `emu/coverage/*.gz` must not change) **in the main checkout** after the change is on
   `main` (`emu/runs/` is gitignored and every worktree's `setup.py`/`phase.py` reads the

   scenario files, including `@tas N` prefixes and resets, to one `.input` script).
   The runner has **no .bk2 support**; `.input` (`runner/input_script.h`) is its format. If
   a per-frame stream is impractical in that format, add one to the engine fork.
3. **K3/K4**: `game.toml` from `build/recomp/` (`seeds.toml` → `[functions] extra`,
   `code_addrs.txt` → `code_addrs_file`, a `[ram_layout]` table is mandatory), GameSpec
   with entry + V-int/H-int through the pointers at `$210/$214/$218`, build.
4. **K5 → K6 → K8**: the first-divergence loop (skill `/first-divergence`). Per-frame
   CRCs come from an `on_frame_post` hook in the game repo (no engine change needed).
5. **K7** alongside: keep `tier3_floor_default = 0` for gating runs; empty
   `dispatch_misses.toml` after each run (engine PRINCIPLES #13a).
6. **K9**, then ask the user for K10.

## Known hazards (from phase 1 and the engine survey)

- **A5 calls.** Every call is `jsr $22+8i(a5)` with A5 = `$200` constant, landing on a
  `jmp (target).l` in the jump table. No `[[jump_table]]` format matches that entry shape;
  without static A5 resolution every call is a computed dispatch. Resolving `d(a5)` with a
  known-constant A5 in the recompiler (engine fork) is the clean fix; seeding the 2,631
  `jmp` stubs is the fallback.
- **Computed control flow**: AI-script `jmp d(a5)` thunk tables entered at offset k,
  `Sw_` switch tables, `Scaler_RowBlocks` (computed entry into 80 unrolled blocks), the
  Nemesis RAM row writer, `Jt_NullTarget` (not a function). All in RECOMP_HANDOFF.md.
- **Bugs to keep**: `AvalonA4_ClearCameraZone`, `Tank_SetTrackLimits`.
- **Self-selecting runtime math**: `Math_LDivS` and friends skip an embedded 68020
  `divs.l` with a `bra`; never generate the 68020 path (`allow_68020_branch` stays off).
- **Never edit generated C** (engine PRINCIPLES #19): fix the recompiler, config or game spec.
- **One runtime instance** (PRINCIPLES #24), but kill it **by PID**, never by image name
  (user rule: `taskkill /F /IM` kills unrelated work).
- No CI exists (the ROM can't be committed): `tools/phase.py 2` and the engine's
  `boot_smoke.py` baseline are the gates; run them before every push.
